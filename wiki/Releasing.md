# Releasing

The release workflow creates a GitHub Release only for a pushed tag of the form `vX.Y.Z`
whose version exactly matches `package.json`.

## Publish a release

1. Update the version in `package.json` and the matching version in `package-lock.json`.
2. Run the complete local checks:

   ```bash
   npm test
   npm run lint
   npm run format:check
   ```

3. Commit the version change, open or update the release branch as appropriate, and merge
   it into `main`.
4. From the merged `main` commit, create an annotated tag that exactly matches the package
   version, then push `main` and the tag:

   ```bash
   git switch main
   git pull --ff-only
   git tag -a vX.Y.Z -m "vX.Y.Z"
   git push origin main --follow-tags
   ```

5. Confirm the **Create release** GitHub Actions run succeeds and inspect the new GitHub
   Release. Its notes are generated by GitHub, so verify that the generated notes cover
   the intended merged pull requests and changes.

If the tag and `package.json` versions differ, the workflow fails before creating a
release. Correct the version or tag according to the repository's release policy, then
push the matching annotated tag.

## Wiki synchronization

Wiki source pages live in `wiki/` on `main`. After changes under that directory are
merged to `main`, the **Sync GitHub Wiki** workflow copies the Markdown pages to the
GitHub Wiki. A maintainer can retry it from the Actions page with **Run workflow**
(manual dispatch).

Before the first automated synchronization, enable **Wikis** in the repository settings
and create a placeholder page in GitHub's Wiki UI. This initializes the separate Wiki
repository required by the workflow. If the workflow cannot clone the Wiki, perform both
of those steps and retry it manually.

The workflow deliberately does nothing when `wiki/` contains no Markdown files; it does
not automatically delete an existing Wiki in that case. To remove a page, delete only
the corresponding source page under `wiki/` as a reviewed change, and verify the desired
effect on the existing Wiki after synchronization. Do not remove all source Markdown
files as a way to clear the remote Wiki.
